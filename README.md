# WBS進捗管理システム (WBS Progress Management System)

Microsoft Project ライクな操作性と直感的な Web インターフェースを兼ね備えた、チーム向け WBS・ガントチャート進捗管理システムです。  
外部データベースの複雑な初期設定なしで、Node.js 環境があればすぐに導入・運用を開始できます。

## 🌟 システム概要と特徴

- **階層型 WBS グリッド & ガントチャート**: 機能と工程（基本設計・詳細設計・実装・単体テスト・結合テスト・受入等）をツリー構造で直観的に管理・インライン編集。
- **担当者マスタ管理**: メンバーごとの1日実稼働時間（8h、時短6hなど）および個別休日・有給休暇を登録可能。
- **工程自動スケジューリング**: 開始日・担当者・予定工数を指定するだけで、会社共通休日と担当者の個別休暇を考慮した日程を自動算出。
- **イナズマ線 (Progress Line)**: 基準日時点での計画進捗率と実績進捗率のギャップをイナズマ線で可視化。遅延工程を一目で把握可能。
- **バーンダウンチャート & 進捗分析**: プロジェクト全体の残工数推移や、工程ごとの先行・遅延ステータスを即時集計。
- **WBS履歴管理・スナップショット**: リスケジュールや要件変更のタイミングでバージョンを丸ごと保存し、過去のスナップショットへ安全に復元（ロールバック）可能。
- **データ自己完結型**: ファイルベースの軽量 JSON ストア（`data/project_store.json`）を採用。外部 RDBMS 等の導入なしで即日稼働できます。

## 💻 動作要件・前提環境

- **OS**: Linux (Ubuntu, Debian, CentOS, RHEL), macOS, または Windows 10/11 (WSL2 推奨)
- **Node.js**: `v18.0.0` 以上（LTS `v20.x` / `v22.x` 推奨）
- **パッケージマネージャー**: `npm` (`v9.x` 以上) または `yarn` / `pnpm`
- **推奨ブラウザ**: Google Chrome, Microsoft Edge, Mozilla Firefox, Safari（最新版）

## 🚀 クイックスタート（開発・検証環境の立ち上げ）

### 1. リポジトリの準備
ソースコードを展開したディレクトリに移動します。

```bash
cd wbs-progress-management
```

### 2. 依存パッケージのインストール
```bash
npm install
```

### 3. 開発サーバーの起動
```bash
npm run dev
```

起動に成功すると、コンソールに以下のように表示されます:
```text
Server running on http://localhost:3000
```
ブラウザで `http://localhost:3000` にアクセスすると、初期データが投入された状態でシステムが利用可能です。

## 🏭 本番環境へのデプロイ・運用手順

### 1. ビルドと直接起動

本番用ビルドを実行し、Vite クライアントアセットと Node.js サーバーをコンパイルします。

```bash
# クライアントアセットとサーバーのバンドル（dist/配下に生成）
npm run build

# 本番サーバーの起動（ポート 3000）
npm start
```

### 2. PM2 による常駐プロセス管理（Linux サーバー推奨）

Node.js のプロセスマネージャーである `pm2` を使用して、サーバーのバックグラウンド常駐および自動再起動を設定します。

```bash
# pm2 のグローバルインストール（未導入の場合）
npm install -g pm2

# ビルドの実行
npm run build

# アプリケーションの起動
pm2 start dist/server.cjs --name "wbs-app"

# サーバー再起動時の自動起動登録
pm2 save
pm2 startup
```

運用監視コマンド:
```bash
# 稼働ステータス確認
pm2 status

# ログの確認
pm2 logs wbs-app

# サービスの停止 / 再起動
pm2 restart wbs-app
pm2 stop wbs-app
```

### 3. Docker / コンテナによる運用

Docker コンテナとしてデプロイする場合の例です。

#### `Dockerfile`（例）
```dockerfile
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
ENV PORT=3000
COPY package*.json ./
RUN npm ci --omit=dev
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/data ./data
EXPOSE 3000
VOLUME ["/app/data"]
CMD ["node", "dist/server.cjs"]
```

#### コンテナのビルドと起動
```bash
# イメージのビルド
docker build -t wbs-app:latest .

# データ永続化ボリュームをマウントして起動
docker run -d \
  --name wbs-system \
  -p 3000:3000 \
  -v $(pwd)/data:/app/data \
  --restart always \
  wbs-app:latest
```

## 💾 データ管理・バックアップ・リストア

本システムでは、プロジェクトデータ、WBS工程、担当者マスタ、履歴スナップショット等の全データが **`data/project_store.json`** に自動保存されます。

### バックアップ方法
`data/` ディレクトリ（または `data/project_store.json`）を定期的にコピー・アーカイブしてください。

```bash
# 手動バックアップの例
tar -czvf wbs_backup_$(date +%Y%m%d_%H%M%S).tar.gz data/
```

### リストア（復元）方法
1. アプリケーションサーバーを停止します。
2. バックアップした `project_store.json` を `data/` ディレクトリに上書き配置します。
3. アプリケーションサーバーを起動します。

## 📖 主要機能と利用の流れ

### 1. プロジェクトの選択・作成
- 画面左上のプロジェクトセレクタから、管理対象のプロジェクトを選択・切り替えできます（全プロジェクト横断表示にも対応）。
- 「新規プロジェクト追加」からプロジェクトを作成できます。プロジェクト管理者は担当者マスタより選定でき、**「本部長」「副本部長」「部長」「課長」**の管理者適格役職のみが選択候補として表示されます。

### 2. 担当者マスタの設定（ヘッダー「担当者マスタ」）
- メンバーの氏名、役割/役職、1日あたりの標準稼働時間（h/日）を設定します。
- **9つの体系的役職階層**:
  1. 社長 (Rank 1)
  2. 執行役員 (Rank 2)
  3. 本部長 (Rank 3) ※プロジェクト管理者適格
  4. 副本部長 (Rank 4) ※プロジェクト管理者適格
  5. 部長 (Rank 5) ※プロジェクト管理者適格
  6. 課長 (Rank 6) ※プロジェクト管理者適格 / タスク担当適格
  7. 主任 (Rank 7) ※タスク担当適格
  8. 担当 (Rank 8) ※タスク担当適格
  9. 研修生 (Rank 9) ※タスク担当適格
- メンバーごとの有給休暇や出張等の個別休日を登録しておくと、工程の自動日程計算時に自動的にスキップされます。

### 3. 休日管理（ヘッダー「休日管理」）
- 会社指定の休業日、祝日、夏季・年末年始休暇などを管理します。
- 内閣府の祝日データやプロジェクト固有の振替休日に対応しています。

### 4. WBS工程の登録・編集
- 「機能を追加」ボタンから、機能名と標準工程（要件定義〜受入テスト等）を一括追加できます。
- 初期担当者や工程担当者は担当者マスタから選択でき、**「課長」「主任」「担当」「研修生」**の実務適格役職のみが選択候補に制限されます。
- 機能行の「⚡（自動日程計算）」ボタンをクリックすると、指定した開始日と担当者マスタの稼働状況・個別休日から、工程日程を一括再計算して反映できます。

### 5. プロジェクト進捗管理画面（WBSテーブル）
- **担当者の選択方式**: 各工程行の担当者列は担当者マスタ（課長・主任・担当・研修生）からの選択式となっており、タイピングミスや不整合を防止します。
- **担当者絞り込みの選択方式**: WBSテーブルのヘッダー担当者列から担当者を選択することで、全プロジェクト横断または特定プロジェクト内でその担当者が関わる工程のみを即座にフィルタリング表示できます。

### 6. 進捗状況の確認とイナズマ線
- ヘッダーで「基準日（進捗確認日）」を設定します。
- ガントチャート上に赤いイナズマ線が表示され、基準日に対して計画より進んでいる工程は右へ、遅れている工程は左へ屈折して表示されます。

### 7. WBSバージョンの保存（ヘッダー「履歴・保存」）
- 設計完了時や大規模なリスケジュールの前に、スナップショット（バージョン名・変更理由メモ）を作成します。
- いつでも過去のスナップショットの内容をプレビューし、ワンクリックでその状態へ安全に戻せます。

## ⚙️ 設定・カスタマイズ

### 待ち受けポート番号の変更
デフォルトではポート `3000` でリッスンします。ポート番号を変更する場合は、`server.ts` の以下の行を変更するか、環境変数 `PORT` を設定してください。

```typescript
// server.ts
const PORT = process.env.PORT || 3000;
```

### リバースプロキシ（Nginx）との連携例
外部からのアクセスを Nginx で受けて本システムに転送する場合の設定例です:

```nginx
server {
    listen 80;
    server_name wbs.example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## ❓ トラブルシューティング & FAQ

### Q1. `npm run build` でエラーが出る
- Node.js のバージョンが 18 以上であることを確認してください（`node -v`）。
- `npm run clean` を実行して既存の `dist/` ディレクトリを削除後、再度 `npm run build` を実行してください。

### Q2. データを初期状態に戻したい
- アプリ右上の「初期化」ボタンを押下して確認ダイアログで「OK」を選択するか、サーバー停止中に `data/project_store.json` を削除して再起動すると、初期デモデータが再生成されます。

### Q3. 複数人で同時に編集しても大丈夫ですか？
- 変更内容は自動保存（Debounce 付き）されサーバー側のストアに反映されます。重要なマイルストーンや変更前には、「履歴・保存」機能でスナップショットを取得しておくことを推奨します。
